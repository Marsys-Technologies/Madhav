# L1↔L2 Relationship Architecture — Decision v1.0

## §0 — Two legacy artifacts purged from the reasoning (read first)

This decision is reasoned from the NEW model only: deterministic data assets, completeness,
retrievability. Two legacy items were corrupting the analysis and are explicitly set aside:
1. **B.1's three-way Facts/Derivation/Interpretation split** ("derivations at the L1/L2.5
   boundary") is **legacy governance** that predates the clean layer model. It is the literal source
   of the "should relationships be L1 or L2?" ambiguity. We do NOT use B.1 to place layers.
2. **SIG.MSR.377** is a **historical note**, not live data, not a live constraint. The "drift
   between two firing engines" concern is resolved structurally below (there is only one engine),
   not by appeal to 377.

## §1 — The decisive technical fact: ga_structural already enumerates, it does NOT predicate-match

Verified in `ga_writers/ga_structural_writer.py`:
- **Aspects, conjunctions, dispositor chains, parivartana, argala (144 cells), composite states,
  avasthas** are generated by **EXHAUSTIVE ENUMERATION** — `for graha in grahas`, `for h in
  range(1,13)`, every-sign × every-sign. They apply the geometric/lordship RULE to every element of
  the chart's combinatorial space. They cannot "miss" a relationship; the space is finite and walked
  completely.
- **ONLY `yoga_fires` / `dosha_fires` use a finite list** — `for yoga_def in YOGA_LIBRARY` (24
  hardcoded). This is the single predicate-bound part, and it's the part that silently drops the
  unlisted.

**Implication:** the relational base is ALREADY built the right way (enumeration). The defect is
that (a) it enumerates over only D1 (~5% leverage — see L0_L1_SENSEMAKING_AUDIT §3), and (b) the
named-pattern layer is predicate/catalog-bound instead of being a label over the enumeration.

## §2 — Why NO predicates for the relational base (native's reasoning, confirmed)

A predicate/registry system (the G52 "500–700 rules") can fire ONLY what someone authored — it is
bounded by the catalog, so it can NEVER cover "any potential native's all relationships." Exhaustive
enumeration is bounded only by the chart's own finite combinatorics — it is complete by
construction. Therefore:
- **The relational base is generated by exhaustive enumeration, not predicate matching.** A
  relationship exists or it doesn't; enumeration finds all; a predicate list finds only the named.
- **Named yogas/doshas are a LABELING pass OVER the enumeration**, not a gate on it. When an
  enumerated configuration matches a classical definition, attach the NAME + CITATION (sourced from
  L0 `brahma_yoga_catalog`, the single definitions source). If it matches no name, the configuration
  is STILL recorded (as an uncatalogued/structural relationship). **The name is an annotation; the
  configuration is never gated by whether a name exists.**
- **G52 as a firing registry is DROPPED.** It survives, if at all, only as the L0 name/citation
  catalog used for labeling — never as the mechanism that decides what gets recorded.

## §3 — What ga_structural HOLDS vs what MSR HOLDS (the clean line)

The L1/L2 boundary is **intrinsic vs. population-level**, derived from one test:
*can this be computed from the chart's geometry alone, or does it require the whole set of
relationships to already exist?*

**ga_structural (L1) — INTRINSIC, per-relationship, geometry-alone, exhaustively enumerated:**
- Every aspect, conjunction, dispositor chain, parivartana, argala cell, composite state, avastha —
  across all vargas + dasha-time-windows (once leverage is fixed).
- The INTRINSIC strength of each (it already emits `yoga_strength_score`,
  `graha_in_house_composite_strength`, `karakatva_strength_per_significance`).
- The NAME/citation label where a configuration matches an L0 classical definition.
- Two-pass verification lives HERE (verification belongs where computation happens).
- It is a DATA ASSET: computed once, stored, ID'd, never re-decided. This is "what relationships
  physically exist in this chart, and how strong is each in itself."

**MSR (L2) — POPULATION-LEVEL, computable ONLY after the full L1 set exists:**
Verified against A10 schema — every MSR-unique column is an operation OVER the whole population of
L1 relationships, impossible to compute from one relationship in isolation:
- `top_k_salience_rank` — this signal's rank RELATIVE TO ALL others in the chart.
- `domain_salience_jsonb` / `domains_affected_array` — per-life-area weighting (needs all signals
  touching a domain).
- `cross_domain_shared_factor_count` — overlap ACROSS relationships.
- `system_convergence_count` — how many traditions AGREE on a signal.
- `contradicts_signals_array` — which OTHER signals this one opposes.
- `computed_salience` — the composed significance score that ranks signals against each other.
MSR holds NO new fact about what exists; it holds SIGNIFICANCE over what exists. It is the layer
that sees the FOREST (rank, convergence, contradiction, domain-emphasis) that no individual L1 TREE
can know about itself.

## §4 — Is MSR truly adding value, or redundant? (the question that decides L1 vs L2)

**MSR is non-redundant — but only for its population-level enrichment.** The test:
- A relationship's INTRINSIC strength + its NAME = computable from the chart alone ⇒ **L1
  (ga_structural).** If MSR recomputed these, it would be a pure copy = redundant.
- RANK / CONVERGENCE / CONTRADICTION / DOMAIN-SALIENCE = computable only over the full L1 population
  ⇒ **L2 (MSR).** This is structurally impossible at L1, because L1 facts are computed
  independently of each other.

So:
- **ga_structural STAYS in L1** — pure deterministic per-relationship fact + intrinsic strength +
  name labels. ✓
- **MSR is genuine L2** — it INHERITS the firing + intrinsic strength from ga_structural (does NOT
  re-fire, does NOT re-derive strength) and ADDS ONLY the population-level layer (rank, convergence,
  contradiction, domain-salience, retrieval shape). ✓
- **What is redundant and must be DROPPED from MSR:** its per-signal RE-FIRING (A10 §0 "evaluate
  every predicate against A1-A9 atoms") and any re-computation of intrinsic strength. Those are L1's
  job, done once.

This is the native's design philosophy realized: convergence + contradiction as first-class L2
artifacts — and now we see WHY they're L2: they are population operations, not chart-geometry facts.

## §5 — The corrected model in one line
**L1 ga_structural = the complete, exhaustively-enumerated, deterministic relational fabric of the
chart + intrinsic strengths + classical name-labels (one engine, no predicates, verification here).
L2 MSR = a pure projection of that fabric enriched with population-level significance (rank,
convergence, contradiction, domain-salience) that is impossible to know from any single
relationship.** No re-firing, no predicate registry, no silent drops, no redundancy, no drift.

## §6 — What this changes in the rebuild
1. ga_structural: enumerate across ALL vargas + dasha-windows (fix ~5% leverage); make named-pattern
   a LABEL over enumeration sourced from L0 catalog (drop the hardcoded 24 + the G52 firing model);
   move two-pass verification here; real fact_ids (drop _mock_fact_id_ref).
2. MSR/bo_laksana: respec from "evaluate predicates against atoms" to "project ga_structural
   relationships + compute population-level enrichment." A10 §0 mission rewritten accordingly.
3. G52 predicate registry: dropped as a firing mechanism (kept only as L0 name/citation catalog if
   useful for labeling).
4. B.1 + SIG.MSR.377: removed from the governing reasoning surface for layer placement.
