# §1 Mission

PR #76 (R6.4 — sidebar layout discipline) landed four surgical edits closing forensic L1 + L2 + plan §7 decision 5. Operator screenshot review 2026-05-18 at 2600px viewport revealed a fifth issue not covered by those four edits: the empty-state hero "Hi {name}, What's on your mind?" renders at ~17% from left of viewport instead of horizontally centered, despite `EmptyState.tsx:25` declaring `mx-auto flex h-full w-full max-w-2xl flex-col items-center justify-center px-4`.

The defeat path: `<ThreadPrimitive.Viewport className="flex-1 overflow-y-auto scroll-smooth py-4">` is a flex-col child of `<ThreadPrimitive.Root className="flex h-full flex-col">`, which itself lives inside `<main className="flex-1 overflow-hidden">`. The Viewport's flex-1 + overflow-y-auto + no explicit horizontal centering rule produces a width context where EmptyState's mx-auto resolves against the wrong containing block. V2Message's centering works because messages render via `<ThreadPrimitive.Messages>`, which uses its own internal rendering pipeline that doesn't traverse the same wrapper chain.

R6.4.1 ships an explicit centering wrapper layer inside `<ThreadPrimitive.Empty>` and simplifies EmptyState.tsx accordingly. Two surgical edits, ~10 LoC.

This brief extracts §3.5 of R6.4 v1.1 verbatim — that section was authored before PR #76 was opened, but the original R6.4 executor prompt (issued before the v1.1 amendment) enumerated only 4 implementation steps. Executor shipped exactly those 4. R6.4.1 picks up the missed work as a dedicated PR per R6.4 §9 fallback path.

# §3 Implementation specification

## §3.1 — `platform/src/components/consume/ConsumeChatV2.tsx`

Locate the `<ThreadPrimitive.Empty>` block. After R6.4's merge it should still be structurally similar to:

```tsx
<ThreadPrimitive.Empty>
  <EmptyState
    chartId={chartId}
    chartName={chartName}
    className="h-full"
    data-testid="v2-thread-empty"
  />
</ThreadPrimitive.Empty>
```

**Target:**

```tsx
<ThreadPrimitive.Empty>
  <div
    className="mx-auto flex h-full w-full max-w-4xl items-center justify-center px-4"
    data-testid="v2-thread-empty-wrap"
  >
    <EmptyState
      chartId={chartId}
      chartName={chartName}
      data-testid="v2-thread-empty"
    />
  </div>
</ThreadPrimitive.Empty>
```

Wrapper className rationale (preserved from R6.4 v1.1 §3.5):

- `flex items-center justify-center` — explicit flex row centering on both axes. Robust regardless of the underlying width-context cause.
- `mx-auto max-w-4xl w-full` — caps at `max-w-4xl` (1024px) to match V2Message wrappers. Visual consistency between empty-state and chat-message column widths so the first-message-sent transition shows no horizontal layout jump.
- `h-full` — fills the Viewport vertically so vertical centering works.
- `px-4` — pulled from EmptyState; the wrap layer now owns it (the inner EmptyState drops it).
- `data-testid="v2-thread-empty-wrap"` — distinct from the inner `v2-thread-empty` testid. Lets future tests assert against either layer separately.

Note the removal of `className="h-full"` from the `<EmptyState>` props call — `h-full` was a prop forwarded to EmptyState's outer div via the `className?: string` prop. Since the wrap layer is now `h-full`, the inner EmptyState fills the wrap layer naturally without needing the prop. The prop is left supported (EmptyState still accepts `className` for API stability) but the V2 caller no longer needs it.

## §3.2 — `platform/src/components/consume/EmptyState.tsx`

Current `EmptyState.tsx:20-36`:

```tsx
export function EmptyState({ chartName, className }: Props) {
  const firstName = chartName?.split(/\s+/)[0] ?? ''
  return (
    <div
      className={cn(
        'mx-auto flex h-full w-full max-w-2xl flex-col items-center justify-center px-4',
        className
      )}
    >
      <p className="font-serif text-center text-[2rem] font-normal leading-snug text-foreground/85">
        {firstName ? `Hi ${firstName},` : 'Hi,'}
        <br />
        What&rsquo;s on your mind?
      </p>
    </div>
  )
}
```

**Target:**

```tsx
export function EmptyState({ chartName, className }: Props) {
  const firstName = chartName?.split(/\s+/)[0] ?? ''
  return (
    <div
      className={cn(
        'flex h-full w-full flex-col items-center justify-center',
        className
      )}
    >
      <p className="font-serif text-center text-[2rem] font-normal leading-snug text-foreground/85">
        {firstName ? `Hi ${firstName},` : 'Hi,'}
        <br />
        What&rsquo;s on your mind?
      </p>
    </div>
  )
}
```

Drops:

- `mx-auto` — wrap layer owns horizontal centering.
- `max-w-2xl` — wrap layer uses `max-w-4xl` for visual consistency with V2Message columns. The hero's natural text width (~600px at text-[2rem]) is comfortably smaller than 1024px so the wider canvas doesn't hurt readability.
- `px-4` — wrap layer applies once.

Keeps:

- `flex flex-col items-center justify-center` — inner alignment for the `<p>` element.
- `h-full w-full` — fills the wrap layer.
