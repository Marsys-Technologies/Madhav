# §1 Mission

F.3 forensic L3: "during streaming, two visually-indistinguishable buttons render at the composer." Operator screenshot evidence: white Square stop button (`v2-abort-btn`, cancels current run) + gold ArrowUp button (`v2-interrupt-send-btn`, cancels run AND re-submits as new query). The two affordances exist for genuine but distinct intents but were never copy-differentiated; users read them as "stop" + "send" of two different states and get confused.

Plan §7 decision 1 chose **right-click context menu** as the canonical resolution: keep only the stop button visible; expose "cancel and send new query" behind a right-click menu. Per the **Option C fast-cutover compromise** declared 2026-05-18, this implementation is deferred to a post-§M.16 polish enhancement. R6.5 ships the **minimal** resolution: delete the interrupt-send button entirely. The "cancel + resend" UX is a niche affordance — users who want it can stop, type, and send (3 actions instead of 1). Most users won't notice it's gone. If post-cutover feedback indicates it's missed, a future R7 brief adds the right-click context menu per plan §7 decision 1.

R6.5 closes smoke spec L3 and removes ~30 LoC of UI + ~15 LoC of unused handler.
