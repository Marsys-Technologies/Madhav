## §3 — SOURCED-INFORMATION PACK (Track B)

**B1 — Consumer inventory.** 100/100 sampled Cloud Run requests (14-day window) carry `User-Agent: Claude-User` — Claude Desktop/Web is the only live external MCP consumer observed. The portal's own chat UI (`platform/src/app/api/chat/*`) does **not** route through MCP at all for its primary path; its cross-model normalizer (`maro/normalizer.ts::stripMcpConstructs()`) explicitly strips `structuredContent` for non-MCP-capable model families (e.g. DeepSeek), confirming at least one internal consumer is text/content-only by design. No GPT/OpenAI-facing consumer route found (OpenAI references in-repo are billing-reconciliation only); a "ChatGPT connector" comment exists in `server.ts` but zero observed traffic matches it. A nightly `audit.ts` cron job calls platform primitives directly, bypassing the MCP tool surface.

**B2 — Request/response logging feasibility.** No mechanism exists today to replay production requests. `trace_emitter` (named in the design doc §31.6) does not exist in the repo — it's aspirational, not built. What exists (`platform-mcp/src/lib/logger.ts`) logs metadata only, and has a real bug: it extracts `req.body.method` (always `"tools/call"`) instead of `req.body.params.name` — **current logs cannot even identify which tool was called**, let alone with what arguments. A minimal capture shim would need to intercept at `transport.handleRequest`, extract tool name+args+response, redact chart_id/PII, and land in either a new DB table or a BigQuery-sinked log export.

**B3 — tools/list footprint.** 124 tools, 55.6KB, ~13.9K tokens (medium confidence, likely a floor — see §2).

**B4 — Battery inputs package.**

Building the shastra map requires either extending `brahma_event_ontology`'s pattern to a new domain×topic table, or deriving correspondences at serve time from scattered per-topic tool logic (no central table today).

No session-level call-chaining exists — `mcp_sessions` and `query_trace_steps` aren't joined; a call-sequence telemetry loop (per §31.6) would need this link built from scratch, not just turned on.
