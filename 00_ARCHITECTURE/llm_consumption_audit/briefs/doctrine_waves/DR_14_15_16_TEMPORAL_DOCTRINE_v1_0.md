# DR-14 — Timing-System Plurality (Daśā Non-Exclusivity)

Activation windows are generated by a PLURALITY of timing systems, each computable from stored
data: the Vimśottarī spine (all levels, including deep sub-periods of non-obvious lords) as the
DEFAULT generator — never an absolute container; Jaimini rāśi-daśās (Chara, Nārāyaṇa);
Tājaka/varṣaphala year-lord + Mudda; Guru-Śani double-transit; aṣṭakavarga-threshold transits;
Saturn/Jupiter/nodal returns; Sāde Satī phases. No system's window may be served as exclusive.
Cross-system confluence raises confidence per the classical multi-pramāṇa principle (the
acharya predicts where independent methods agree — dvi-pramāṇa generalized). Per-system weights
are LEARNED (D-4b hierarchical calibration), never assumed; until fitted, weights serve as
classical structural priors with `calibration_state` disclosed. Evidence anchor: the LEL's own
Chara-daśā match on EVT.2024.02.16 while the Vimśottarī lens was unremarkable.

# DR-15 — Ensemble First-Class + Proper Scoring

(a) The confluence ENSEMBLE (weighted superposition of generators/peak-models) is a first-class
contender in every model comparison — several peak-logics coexisting within one window is a
legitimate, servable, multi-modal density, not a contradiction to resolve. (b) Model comparison
uses PROPER SCORING RULES (CRPS/log-score) against mirrored reference forecasts (the model's own
coverage-matched shuffled-birth control); skill = 1 − CRPS_model/CRPS_control. Hit-rate (±45d
top-decile) is retained as a legacy secondary metric for continuity with D-3's baseline.
(c) Every scoring loosening applies identically to controls (inherits DR-13's mirroring rule).
(d) Pre-registration: thresholds, event sets, and win criteria commit to the ledger BEFORE any
scoring run; post-hoc adjustment is gate-gaming.

# DR-16 — Adverse-Window Disclosure (with the Honest-Clarity Principle)

Governs every served inauspicious/adverse window, D-5 onward.

1. **Honest clarity is co-equal with restraint** (native directive 2026-07-19): the consumer is
   an educated, consenting adult. Adverse windows are stated CLEARLY and SPECIFICALLY — domain,
   window, mechanism, and what elevated risk means in practice. Vagueness, euphemism, and
   information-withholding are themselves disclosure failures, recorded as defects of the same
   severity as over-claiming.
2. **Always probabilistic, never fatalistic:** served as elevated hazard for an event-CLASS
   ("finance-domain loss-risk elevated in [window]; mechanism: X; this chart's history: fired N
   times"), never as a certain or scheduled misfortune. No death-date, ruin-date, or
   catastrophe point-claims — the system does not serve lifespan or doom assertions, and the
   sweep horizon is uniform birth+100y for every chart precisely so that no infrastructure
   encodes a longevity opinion.
3. **Falsifier-bearing:** every adverse claim carries its falsifier and enters the prospective
   ledger like any other claim — adverse claims are scored, and their calibration (or lack) is
   served with them.
4. **Mitigation-paired:** an adverse window is never served bare — the suppression analysis
   (what damps it) and the remedy-leverage surface (what the tradition prescribes, BPHS-cited)
   ship in the same payload, with the same clarity standard.
5. **Confidence honesty:** `calibration_state`, n_observations, and control delta accompany the
   claim; structural-prior adverse claims say so plainly.
6. **Tiering:** disclosure tiers per MACRO_PLAN's Ethical Framework govern non-native consumers;
   for the native (research mode), full-detail serving is the default per (1).
