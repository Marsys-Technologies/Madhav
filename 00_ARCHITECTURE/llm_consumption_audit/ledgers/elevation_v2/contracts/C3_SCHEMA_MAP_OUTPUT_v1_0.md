# C3 — schema-map output shape

## Problem this closes
`fact_category` already has one authoritative, mechanically-generated census
(`chart_facts_categories_authoritative_v1.json`, 218 categories, `SELECT DISTINCT fact_category FROM
chart_facts`) that explicitly supersedes three stale sources
(`CHART_FACTS_SCHEMA.json`, `coverage_matrix.ts`, `ganita/types.ts`). No equivalent census exists yet
for `fact_subjects` or `fact_keys`, and no concept-alias table seeded from the Phase-0.7 census
exists. γ's TCI is generated from this output and must never be stubbed — so the generator (built
separately, see the schema-map generator task) must actually run against a live chart, not return
canned data.

## Frozen output shape

```ts
export type SchemaMapEntry = {
  fact_category: string;                 // one row per (category, subject) pair actually present
  fact_subject: string;
  fact_keys: string[];                   // sorted, deduped keys observed under this (category, subject)
  row_count: number;                     // rows in chart_facts matching this (category, subject)
  sample_fact_ids: string[];             // up to 3, for spot-check tracing back to chart_facts.fact_id
};

export type ConceptAlias = {
  concept_id: string;                    // canonical id from the Phase-0.7 census
  aliases: string[];                     // surface strings observed to route to this concept_id
  fact_categories: string[];             // fact_category values this concept_id resolves through
};

export type SchemaMap = {
  chart_id: string;
  generated_at: string;                  // ISO-8601, stamped by caller (script cannot call Date.now())
  source: "live DB — chart_facts, mechanically enumerated";
  entries: SchemaMapEntry[];             // paginated per C1 if large
  concept_aliases: ConceptAlias[];
  pagination: { offset: number; limit: number; total: number; next_cursor: string | null };
};
```

## Rules (frozen)
1. `entries` MUST be generated by literally enumerating `fact_category × fact_subjects × fact_keys`
   against a live chart's `chart_facts` rows — no hand-authored category list, mirroring the
   existing `chart_facts_categories_authoritative_v1.json` pattern (which already rejects the 3
   stale hand-authored sources for exactly this reason).
2. `concept_aliases` MUST be seeded from the Phase-0.7 census output (whatever that census's schema
   turns out to be) — this contract fixes the *output* shape (`ConceptAlias`), not the census
   generation itself, which is a separate build step.
3. Output is paginated per C1 (`budget_kb`, `pagination`, `more_available`, `next_cursor`) — a full
   218-category × N-subject enumeration will not fit a single response.
4. The generator MUST be re-runnable (idempotent) against any chart_id — γ's TCI depends on this
   being real, live-generated data, never a stub or fixture.

## Non-goals
- Does NOT define how `fact_subjects` are canonicalized (e.g. whether "Sun" and "sun" collapse) —
  that's a generator implementation decision, this contract only fixes the shape once decided.
- Does NOT replace `chart_facts_categories_authoritative_v1.json` — `SchemaMap.entries` is a finer
  enumeration (category × subject × keys) that is a strict refinement of that file's category list.
