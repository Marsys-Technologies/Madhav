# REPORT_PB-3 — SAMĪKṢĀ wave close

**Disposition: SHIP-DEGRADED.** The wave is CLOSED, not PASS — merged and deployed, with a known, honestly-disclosed defect class carried forward as PARKED follow-up (PB-3.1), the same disposition class PB-2 closed under.

**Headline: PB-3 is inert in production — no live entry, no live exit.** It built and merged a complete, individually-tested prediction lifecycle — capture, confirm, kāla-rekhā timeline, review tab, daily-window closer, outcome resolution, Brier calibration, and a no-leakage guard — and every one of those six lanes' own tests passed. But the loop has no live entry: the single UI affordance that would carry a real detection into the ledger is unmounted on every live route, so `brahma_mimamsa_prediction_ledger` holds zero rows on every chart despite six real predictions being detected in live readings. And it has no live exit either: the daily job that would close a window silently no-ops on a misconfigured secret and reports green forever, and the resolve action — though genuinely live-mounted — calls a locally re-implemented outcome map instead of the Brier recorder the wave built, which itself has zero live callers. Every downstream stage (dock card, review tab, daily job, outcome resolution, Brier scoring) is consequently either unreachable or has nothing to act on. Six green lane-reports do not aggregate into "shipped." This report is the honest correction of that gap.

Verified against: `origin/main` (`368527e2`, all lanes L-1–L-6 merged via PRs #868, #871–#876), production Cloud Run service `amjis-web` (asia-south1, revision `amjis-web-01271-6kt`), production Postgres (read-only queries throughout; no row was ever hand-inserted). Five independent fresh-context gate-runner agents executed this gate; findings below are synthesized from their evidence, not asserted from priors.
