## DISAGREE reproductions

### 1. Build.completion — all 12 sampled assets — census `N/A, "no count_sql"` is false

Census: `"v": "N/A", "measured": "no count_sql; build state='lit'"` for every L1 asset.
Truth: `count_sql` **is registered** for all 12:

```sql
SELECT asset_id, count_sql IS NOT NULL FROM asset_registry
WHERE asset_id IN ('ga_ayurdaya','ga_condition','ga_dashas','ga_nakshatra','ga_positions',
 'ga_prashna','ga_vargas','ga_strength','ga_structural','ga_tajaka','ga_transit_anchors','ga_yoga');
-- all 12 = t
```

e.g. `ga_vargas.count_sql = 'SELECT count(*) FROM chart_divisionals WHERE chart_id = $1'`.
Furthermore the protocol's completion comparison is computable and would **not** be vacuous:
`asset_throughput.rows_written` (latest lit row) vs live `count(*)`:
ga_vargas **24400 vs 0**, ga_tajaka 240 vs 780, ga_condition 45 vs 135, ga_transit_anchors 45 vs 135 —
mismatches the N/A verdict hides (the discrepancy is partly semantic: `rows_written`/`count_sql` are
per-chart while the live count is global; but "no count_sql" is simply wrong, and ga_vargas's
`chart_divisionals` being empty while reporting 24400 rows written on 2026-09-07 is a real
completion anomaly the census should have surfaced).

### 2. Build.exercised — ga_dashas — measured count off by one

Census: `"108 run(s), scope(s): asset, asset_set, global, layer, last 2026-09-07"`.
Truth:
```sql
SELECT count(*) FROM build_run_assets WHERE asset_id='ga_dashas';  -- 107
```
Scopes and last date agree; verdict PASS unaffected; the count 108 does not reproduce.
