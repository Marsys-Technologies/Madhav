# Autonomous Asset Elevation — Madhav Adoption

Madhav adopts `$autonomous-asset-elevation` as the reusable implementation method for Nirmana
layer and asset elevation. The tracked skill bundle above is the single maintained source for the
generic master plan, per-asset contract, swarm runtime and machine-readable execution packets.

## Outcome

The method optimizes one headline: assets reaching an accepted terminal disposition and complete
layers frozen. Commits, pull requests, tests, reviews, agents and reports remain supporting evidence,
never progress by themselves.

It provides:

- sequential layers with DAG-safe parallelism inside the open layer;
- asset-by-asset purpose, dependency, correctness, data, reuse, AI/UI and efficiency analysis;
- isolated worktrees and write ownership;
- elastic, proportionately routed agents with a Native Surrogate and anti-idle monitor;
- protected integration, deployment, one accepted production rebuild and independent freeze proof;
- event-derived tracker truth and production/main reconciliation;
- bounded cleanup after durable acceptance.

## Madhav override and precedence

The generic skill never overrides the frozen Nirmana campaign contract. For Nirmana execution,
authority and precedence are:

1. fresh accepted database definition/events, protected Git, live production/database and the
   authenticated tracker projection;
2. `00_ARCHITECTURE/NIRMANA_ELEVATION_PLAN_v6_0.md` and
   `00_ARCHITECTURE/autonomy/CHARTER_v2_0.md`;
3. `00_ARCHITECTURE/NIRMANA_ELEVATION_CONTEXT_PACK_v6_0.md` after revalidating time-sensitive facts;
4. historical ledgers, seals and `lit` state as evidence only.

Nirmana therefore retains its mandatory state machine:

`BOOTSTRAP -> T0_CENSUS -> PLAN_FROZEN -> DENOMINATOR_FROZEN -> F0_FOUNDATION -> L0 -> L1 -> L2 -> L3 -> L4 -> L5 -> CLOSING -> COMPLETE`

T0 performs no rebuild. F0 must be deployed and independently accepted before the first L0 accepted
rebuild. A canary proves machinery, not an asset. Producer-covered assets inherit producer evidence
and are not rebuilt twice.

## Invocation

Use `$autonomous-asset-elevation` in stocktake, plan, execute/resume or audit mode. Current counts,
SHAs, task ownership and lifecycle events remain in the live campaign control plane, never in this
adoption record or the reusable skill.
