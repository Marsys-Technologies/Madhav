# Kāla elevation blueprint

**The goal, in the native's words:** a highly enriched, elevated Kāla layer, every asset elevated,
each asset's individuality protected, the assets synergizing to produce the best value for the
user — whose experience is the primary goal — on an environment set up so that both consulting the
layer and building a chart into it are seamless.

**The measure of success, in the product's words:** *"I understand something consequential that I
could not see before. I see the connected basis, the alternatives, the timing where support
permits, and what remains uncertain. I can challenge it, revisit it and tell whether the product
was wrong"* (Product §1). Kāla's share of that is temporal discrimination: *"which enduring
structures are engaged, how and when"* (§3.10).

  overlapping windows, recurrence and possible manifestations. Move between a life chapter and a
  narrow interval without changing evidential identity."*

it always means *not large enough to see at this n*, never *nothing there*, and every E6 report says
which. Anything short reports `PROVISIONAL_INSUFFICIENT_N` with its actual n. A passed gate is
`BINOMIAL_GATE_PASSED`, never `EMPIRICALLY_EVALUATED` (M-6's five preconditions stay closed).

## §13 — The learning loop: window → claim → outcome → recalibration

The product's definition is calibrated, testable, correctable prediction (Product §7). Kāla owns
the *window*; it does not own the claim, the outcome or the calibration — but the loop runs
through it, and v4.x never said how. Stated once, with each firewall named:

```
Kāla window ──► L4 ph_nimitta (phala_anchors)  ──► L5 mi_bhavisya: FROZEN CLAIM (DP15a)
  kala_convergence / kala_bhavishya                 window_start/end frozen verbatim
  (Publication-handoff objects only)                 from Kāla's fields (Lane F §1b)
        │                                                     │
        │ knowledge time pinned (F15)                          │ exposure
        ▼                                                     ▼
  E6 exposure manifest (ka_sangam/exposure.py)   ◄──  LEL observation (life_events / mi_jivanaghatana)
  stratum = (domain × route × method_version)         mi_pramana adjudication (DP15b)
  n=20/50 binomial gate → PROVISIONAL_INSUFFICIENT_N | BINOMIAL_GATE_PASSED | CENSORING_BLOCKED
        │
        ▼ NOTHING flows back automatically (F18)
  a separately admitted artifact (DP18): kala_field_weight_versions · kernel_version · convention_id · generation
```

1. **Which Kāla objects may become claim candidates.** Only Publication-handoff objects — a
   `kala_bhavishya` row, a `kala_darshana` window via `phala_anchors`. Never a raw `kala_activation`
   period, never a `kala_field` segment, never a service response. The candidate carries the
   window identity (SC-3) so the frozen claim can be traced to the exact producer row and
   generation.
2. **Issuance freezes Kāla's grain.** L5 freezes `window_start/window_end` verbatim; Kāla's
   DATE grain therefore *is* the claim's precision today. SC-1 (timestamptz) changes what a future
   claim can say; it must never change an issued one (F17).
3. **Outcome never re-enters generation.** `phala_rectification` stays denied to Kṣetra (ruling 3);
   `mi_bhara` reads `kala_field` and writes `kala_insights.lel_derived=true`, which Kṣetra never
   deletes; no writer reads `mimamsa_*` or LEL (Strategy §6.2, U09).
4. **E6 is the door to tier 3.** The exposure manifest is attached to `WriterResult.notes` (the
   only carrier the frozen contract offers); the gate can only see large effects (§8). B-6:
   `evaluation_eligible` / `is_synthetic` have no source field yet — a consent/synthetic marker in
   chart metadata is the native's/L1's.
5. **What changes in Kāla when the gate passes or fails.** Nothing, by itself. A passed stratum
   licenses a *proposal* for a new admitted artifact: a `kala_field_weight_versions` row (Kṣetra),
   a `kernel_version` (Saṅgam), a `convention_id`/generation (Gochara) — each versioned, each
   separately admitted, each leaving the prior generation intact. A failed or censored stratum
   changes the *qualification* served (SC-2), never the computation. This is the recalibration
   hook, and it is a governance step, not a feedback wire.
6. **Every brief declares its position in this loop:** which of its outputs is a claim candidate
   (usually none), what it freezes for issuance, and what artifact would carry a recalibration.
