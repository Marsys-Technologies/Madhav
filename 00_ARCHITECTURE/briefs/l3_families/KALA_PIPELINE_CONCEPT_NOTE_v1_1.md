# The Kāla pipeline — concept note (v1.1, reconciled)

**One sentence.** Gochara, Saṅgam and Kṣetra each answer "when does this happen in this life?" by recomputing the same sky, the same promises and the same clocks and storing the result three ways; this note makes them three stages of one pipeline over one shared object, so that every distinct capability survives in a form that can be evaluated, nothing is built twice, and no stage is served before it has earned its place against the native's lived events — with the honest caveat, from the review, that with one chart and forty-seven held-out events most of that earning is structural and prospective, not statistical.

## 0. What this note is, and is not

- It **is** the concept for the doctrine reviews and design specs that follow: stage boundaries, the shared object, the shared foundations, the evidence algebra, the measurement contract, and the test each stage must meet.
- It is **not** a build authorisation, a migration, a data change, or a doctrine seal. Every number is measured read-only, cited to a recon with its query, taken from the review `[A]`, or labelled `[I]`.
- **What the partition is, stated plainly (Astra A1).** Judge / jury / forecaster is a software partition, not the classical order of inference. The classical reading discipline — promise → period → transit → day → qualify — is a computation strategy (Gochara v3.0 §2.1). Each school's *complete* rule, including its own exceptions (e.g. BPHS 70.12–14's favourable-daśā exception to an adverse transit result `[A]`), is evaluated inside the judge. The jury compares completed, source-qualified judgments. The forecaster measures their usefulness. No stage repairs an incomplete classical rule by adding a score.
- It **supersedes the scope** of the per-asset Saṅgam final brief. Per-stage briefs on the asset-elevation template follow at spec time (§11).
- **Open ruling:** F-6 (Mode D) remains `requested` on the tracker; §5.4 makes it a design consequence rather than a separate choice.

## 2. The shared object: assertion, forecast, outcome

v1.0 had one object. The review showed that one object conflated three things with different lifecycles. v1.1 has three, linked.

```
assertion            one evaluated statement by one method about one subject and interval
  id · chart · generation · stage (judge|jury|forecaster) · method (path_id|group_id|model_id) · rule_version
  subject {event_class, affected_person, objects[]}  · frame · period_anchor {system, MD, AD, PD?, applicability}
  interval (half-open) · grain {year|era|month|week|day}
  role ∈ {selects · conditions · qualifies · corroborates · explains}        ← the evidence algebra, §5.3
  roots {contact_ids[], record_ids[], fact_ids[]} · derivation_parents[] · used_for_selection (bool)
  source {text, locator} · provenance {verse_cited|uncited_extension} · operator_role {scored|testimony}
  value fields per stage (judge: evidence_for/against, valence, severity; jury: D(W), segment support;
                          forecaster: alignment_null_p, intensity, integral, odds (only if §6.2 holds))
  null_reason (typed, §6.4) · coverage_ref · precision {method, Δλ, Δt}

issued_forecast      an immutable claim issued at a time, from an information cutoff, about an event
  forecast_id (canonical: one per event identity, many reading attachments — Astra K17)
  issued_at · information_cutoff · birth_params_version · pipeline_manifest_ref (§3.4)
  event {class, affected_person, phase ∈ {onset|culmination|approval|implementation|recovery|recurrence}}
  interval(s) (disconnected allowed) · point_functional (declared: peak|mode|median) · resolution
     {computation, source_licensed, empirically_supported}  — disclosed grain = the weakest (Astra C6)
  probability_target (nullable; only when §6.2's event model is declared) · interval_level (nominal, nullable)
  assertion_ids[] · reading_attachments[] (L2 signal ids) · samiksha_ledger_ref (nullable)

outcome              what happened, recorded independently of any forecast (F3, §3.3)
  observation axis   ∈ {hit · miss · ambiguous · censored · unobserved}   (with exposure manifest)
  derivation axis    ∈ {valid · invalidated · superseded}                   (never erases the observation)
```

Invariants (carried into oracles):

1. No assertion restates an L1 value; it references `fact_ids` (§N.5). Narration over assertions selects by pinned key and total order (§N.7).
2. Every undeterminable field is **null with a typed reason**, never a favourable-sounding default (ADK-0026).
3. `generation` is NOT NULL; nothing is shared across generations; an absent authority row means `unpublished`.
4. The jury and forecaster never admit or exclude a window; only the judge's path prerequisites do.
5. Testimony (`operator_role = testimony`) contributes zero to any score, weight, gate or evidence increment **in every stage** (D-PADMIT; Astra F1-5).
6. An issued forecast is never edited; refinement issues a new forecast with a new cutoff. A later invalidation of its derivation changes the derivation axis, not the observation.
7. Duplicate records, lord aliases, and relocating a computation between stages must not change any stage's result (Astra A2).

## 3. The shared foundations, and the storage pattern

### 3.1 F1 — the signed mechanism graph (promise)

- **Source:** authoritative **L1 facts + versioned L0/source rules → signed mechanism graph**. The reading's MSR/CGM mechanisms **attach** reviewed interpretations and links and **project** from it; they do not define the universe of promise (Astra K11/E3; §N.5). A reading may omit a mechanism for editorial or detector reasons; absence of an L2 signal is not denial.
- **Content:** supporting and adverse mechanisms; preconditions, exceptions, cancellations; subject and frame; source qualification and rule version; `missing_fact` vs `evaluated_empty`; event-class mapping as a separate, reviewable inference.
- **Replaces:** `ka_yojaka`'s predicate table (the 79 orphans are the symptom), Kṣetra's promise stages, and — subject to a Pravāha amendment — the judge's natal-fact rows as projections (coordination item, §8.5).
- **Idempotency:** per `(chart_id, generation)` delete-then-insert (§N.3), generation-scoped.
- **Not carried:** W2's default conductance / noisy-OR arithmetic as "classical promise strength" (Astra E3).

### 3.2 F2 — the clock service, with correct uncertainty

- **Service:** `period_context(chart, t, system) → {MD, AD, PD, applicability, σ}` and `boundaries(chart, system) → [(instant, σ, scenario_id)]`; applicability per system evaluated and stored (Aṣṭottarī `absent` on this chart; Chara for Jaimini targets; annual periods inside P9 per the chosen Hāyanaratna construction — ch. 7 has several, not one universal Mudda `[A]`).
- **Defect carried in, fixed once:** the shipped propagation adds the birth-time contributions in quadrature although both derive from the same `dT` (`services/ka_kshetra/uncertainty.py:268–276` `[S]`). With `k = K/L` (period length over angular span) and `v` the Moon's rate, the linearisation is `dB = (1 − kv)dT + k dA`, so `Var(B) = (1−kv)²Var(T) + k²Var(A) + 2k(1−kv)Cov(T,A)` (Astra K09). Near nakṣatra/pāda or applicability boundaries the linear form is inadequate: recompute whole scenarios. Boundaries share their uncertainty; they are never perturbed independently.
- **Kinds of uncertainty kept apart:** numerical (solver bounds — not Gaussian σ), parameter (birth time, ayanāṃśa — alternative conventions are *not* random samples), predictive (rule/model error). Only the last two reach an interval on an issued forecast, and only after §6.6 validates it.
- **Expressiveness vs precision:** sūkṣma and prāṇa levels are representable (BPHS 62.1, 63.1 `[A]`); representing them licenses no forecast grain (§2 resolution rule).
- **Also fixes once:** Kṣetra rank-3a (boundaries read `chart_dashas` without `ayanamsha_id`).

### 3.3 F3 — the outcome record and frozen data roles

- **One record, two row kinds:** events (LEL-derived, dated, class- **and phase-**tagged, with grain and a shared `episode_id` where events belong to one transition) and resolutions (Samīkṣā: hit / miss / unverifiable, Brier-eligible by its existing predicate). Exposure manifests state which periods were observed.
- **Frozen roles (Astra K04):** `development` (the registry's development events, worked examples), `calibration` (reserved; empty until prospective data exists), `test` (the 47 held-out, untouched). Every adaptive use of any row is logged; a row used adaptively leaves the test role permanently. Nothing is learned from the test role. "Held-out" is never said of a row that trained anything.
- **What can be learned now** (Astra D3, arithmetic: 47 events / 27 classes ≈ 1.7 per class; 30 timing-usable; 5 exact-date; four held-out events across all six Tier-A classes): structural correctness; source fidelity; rejection of blanket-window behaviour; paired descriptive comparisons of a few predeclared pipeline variants; a prospective protocol. Per-path, per-group, per-class weights and calibration curves are `PROVISIONAL_INSUFFICIENT_N` until prospective issued forecasts accrue (n ≥ 20 per stratum, ≥ 50 instrument-level, as E6 set; ≈ 97 independent trials for ±0.10 at p≈0.5 `[A]`).

### 5.3 The evidence algebra (replaces R1–R5)

1. Every assertion carries `role`, `roots`, `derivation_parents`, `method`, `rule_version`, `period_anchor`, `used_for_selection`.
2. An assertion whose roots or derivation parents were used to **select** the candidate window can `condition` or `explain` it; it cannot `corroborate` it. P8-admitted windows are therefore never G-J-corroborated (Astra K05).
3. A reused root (same `contact_id`, same ladder, same AV table, same vedha interval, same Moon contact) yields **no evidence increment** in a later stage, whichever service recomputed it; recomputation is not independence (Astra A2).
4. Intersecting a window with a clock interval that already bounded it adds no information and is recorded as `explains`, not `corroborates` (Astra A2-2).
5. Testimony adds nothing in any role but `explains`.
6. Shared dependencies are declared per group (§5.2 columns) and preserved in every null replicate (§5.4).
7. Idempotence: duplicates, aliases and relocation change nothing (§2 invariant 7) — oracles mutate each and assert equality.

### 5.4 Agreement, measured (replaces counting currents; closes F-6 by design)

- **Segments.** Form elementary half-open segments from the union of all relevant boundaries. Each segment carries its support vector: which groups' assertions support it, with roles. "Joint agreement" is support on the **same** segment, never pairwise overlap somewhere inside a broad window (Astra B1: `W=[0,30), A=[0,1), B=[29,30)` has no joint segment).
- **Measure (centred difference, Astra B2).** For an eligible window `W`, `q_g(W) = |A_g ∩ W| / |W|` over groups eligible to corroborate (§5.3), and `D(W) = Σ_g w_g { q_g(W) − E_0[q_g(W) | C] }` with fixed, disclosed weights `w_g` and conditioning information `C` (selection history, opportunity mask, shared dependencies). Invariants: a universally active witness contributes 0; duplicates and aliases change nothing; missing or inapplicable witnesses are not negative votes; zero null variance gives an explicit non-informative state; the quantity is never called probability, odds or confidence; window length, coverage, grain and witness signature accompany every comparison. Ratios, likelihood ratios and posteriors are not used until their likelihoods and priors are specified.
- **Two analyses (Astra B1):** (i) **incremental corroboration** — condition on the judge's selection and the eligible risk set; test only the additional information; preserve shared dependencies in each resample; (ii) **whole-pipeline separation** — repeat candidate selection, segmentation and maximisation inside every null replicate. The null is age/opportunity/calendar-matched where the estimand needs it; the existing seed-482012 controls are kept for comparability. Where exchangeability cannot be justified, the result is reported as a **surrogate alignment diagnostic**, not a p-value. Monte-Carlo tails use `(b+1)/(R+1)` (Phipson & Smyth 2010 `[M]`).
- **Grain (Astra B3).** Methods are compared at their licensed scale: an annual witness discriminates years, not weeks; a week-scale witness is assessed against its eligible weeks. No inverse-fraction weighting. Report supported vs eligible duration, method resolution, incremental discrimination within the parent window, coverage, and the uncertainty of the improvement.
- **Mode D** is thereby retired as a row producer: an ingress window that admits most of the century has `q_g ≈ E_0[q_g]` and contributes ≈ 0.

### 5.5 Attaching the reading's claims (canonical forecasts, many attachments)

- Each L2 signal that names an **observable event predicate** maps through F1 to `(event_class, phase, affected_person, objects)`. Signals that state traits, conditions or lifetime tendencies are not registered (Astra cut list).
- One **canonical forecast per event identity** (class, phase, person, episode); reading signals attach to it. Evaluation is clustered by event and shared episode; no event is credited twice (Astra K17).

### 5.6 Turning points, sequences, contests

- **Turning point:** corroborated forecasts in different domains sharing a segment → one row with members, segment, domains and `D`.
- **Sequence:** three things kept apart (Astra C3) — *textual temporal rules* (BPHS 47.3–4 ordering, Kālacakra transitions, Tājaka configuration states) belong in the judge's method; *real-world eligibility* (child after marriage, etc.) belongs in the event's risk set; *narrative sequence hypotheses* remain labelled expectations. None is presented as physical causation.
- **Contest:** mutually exclusive forecasts corroborated on one segment stand together, flagged `contested`; never averaged.

The disclosed grain of the resulting forecast is the weakest of computation, source-licensed and empirically supported resolution (§2); `year` is a legal grain; disconnected intervals are kept rather than forced into one peak and a symmetric margin.

## 6. Stage 3 — Kṣetra, the forecaster

### 6.1 Boundary and the continuous field, kept compact

**Reads:** judge and jury assertions; F2; base rates; F3 (through L5 roles only).
**Writes:** the compact field, alignment nulls, windows-above-null, salience, insights, view projections, the published snapshot.
**Must not do:** compute promises or clocks; read L4 directly; materialise dense century rows; call an alignment tail an odds.

**The field (Astra K07/E1, B8-6).** A compact, evaluable representation is kept: piecewise log-linear segments with breakpoints, coefficients, risk/observation masks, the integral `∫λ`, and uncertainty scenarios — enough to reproduce W2's likelihood `Σ_k log λ(t_k) − ∫λ(t)dt` and to penalise intensity over uneventful exposure. Dense rows are deleted only when the evaluator reproduces the function (byte-equality test on sampled instants and integrals). **Knots:** per B8-6, Kṣetra's continuous kinematics remain its knot source and are evaluation-only (never served as a contact); a shared continuous-geometry substrate may replace them **only** after an equivalence demonstration and an explicit amendment (coordination item). Scoped suppression is kept as route-specific distinctions (less favourable delivery · delayed delivery · reduced occurrence intensity) — not as inherited multipliers, positive floors or promise defaults (Astra cut list).

### 6.2 Chance, alignment, and odds — three different things

- **Alignment surprise** (the null of §5.4, owned here, shared with the jury): per-claim, conditional, with the whole-pipeline variant; `(b+1)/(R+1)`; reported as `alignment_null_p` or as a surrogate diagnostic. One null machinery; no second p-value layer that repeats the jury's test (Astra E2).
- **Sourced prior** (§6.3): a population or cohort rate with provenance. Not a forecast.
- **Calibrated event probability:** issued **only** when a declared event model exists — for a first-event hazard with a declared risk set, `P(W) = 1 − exp[−∫_W λ(t)dt]` — and only after §6.6 K2 has evaluated it on prospective issued forecasts. Until then `probability_target` is null and the view says why.

### 6.3 Base rates — two axes

Each class carries **baseline provenance** (`population_sourced` with citation, cohort and year · `cohort_conditioned` · `none`) and **forecast calibration status** (`uncalibrated` · `provisional_insufficient_n` · `calibrated`). The six classes migration 571 labels "calibrated" are relabelled **source-labelled priors awaiting qualification**: their inputs (ever-married prevalence, fertility, migration prevalence, surgical prevalence …) are not incidence per person-time for a forecast window (Astra D2). The reference-class route per class: define onset/recurrence/severity; define age, sex, geography, period and eligibility; obtain incidence or a survival model; represent transportability; validate forecasts separately. **No odds are served** for any class whose calibration status is not `calibrated`; agreement and rules are shown instead, with the reason. Synthetic chart cohorts estimate configuration frequency, not human base rates.

### 6.4 Negative space — six states (Astra C2, K10)

`outside_risk_set` · `method_inapplicable` · `information_unavailable` · `evaluated_silent` · `obstruction_active {what, by what, interval, release}` · `measured_lower_rate {support}`. Only the last two can support a negative forecast, and they are not interchangeable. "Expect quiet" requires a complete observation mask, a class-specific negative rule (e.g. BPHS 70.12–14-type exceptions; BPHS 50.20–25 bādhaka conditions `[A]`) or a tested conditional rate reduction. No universal bādhaka or māraka multiplier.

### 6.5 Rectification — an evidence update, not a narrowing (Astra K15, C5)

A resolved outcome updates the birth-time/ayanāṃśa scenario set through L4 rectification → L1 → F2 as a governed L5-initiated generation. The update may **narrow, widen or split** the uncertainty. Rules: a separate rectification evidence partition disjoint from the test role; an immutable evidence cutoff; explicit model assumptions; every issued forecast preserved under its original parameters; a ±10-minute survival test is sensitivity over a chosen range, not a confidence interval. Classical lost-horoscopy (BPHS 78.1–9 `[A]`) is query-based reconstruction, a different problem; event-based and nāḍī methods need their own source review before admission.

### 6.6 Attention, views, snapshot, tests

- **Attention:** salience axes I/Q/R/B/A kept; the composite product (odds × consequence × actionability × imminence) is **deferred** until its units, null handling and justification are specified (Astra E2). Insight types kept; "absence of the expected" is served only as the typed state §6.4 allows.
- **Views:** the seven read from assertions and forecasts; common semantics are stabilised before all seven are built.
- **Snapshot:** published by the §3.4 manifest with an independently recomputed content digest; dependency mutations must change it.
- **Tests** (four-way verdicts):

| Test | Pass condition | Repair from the review |
|---|---|---|
| K1 null discrimination | `alignment_null_p` lower on held-out hits than on matched controls, conditional null, predeclared endpoint | selection-aware null |
| K2 reliability | on **prospective issued forecasts** with observed exposure, non-events and censoring, stated probabilities match frequencies within a declared tolerance; Brier via Samīkṣā's predicate | not evaluable on the positive registry alone → `not_evaluable` until prospective data exists |
| K3 interval quality | proper interval score at the nominal level, with width penalty and miss accounting, better than a baseline interval | coverage alone is insufficient |
| K4 axis oracle | several registry events across epochs, boundary and timezone cases place correctly; a mutant that mixes J2000 and birth-relative axes fails | not a single event |
| K5 reproducibility | identical complete inputs → identical digest; each dependency mutation changes it | recomputed digest |
| K6 quiet periods | periods flagged `measured_lower_rate` show a lower held-out rate than the class base rate under a verified observation mask | masks required |
