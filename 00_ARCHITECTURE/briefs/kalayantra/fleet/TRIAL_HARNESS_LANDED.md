## AMD64-DOCKER (item amd64-docker: ruling SR-T24-AMD64-DOCKER, owner surrogate madhav-44; TR blocker T24/B8)

The one linux/amd64 slice of a TR head runs **in a linux/amd64 Docker container on this Mac** (Docker Desktop emulation), against a **PG 15 / locale C sibling container** on a private (`--internal`) docker network. No paid cloud, no GitHub-hosted runner; chart data never leaves the Mac (no image push, no artifact upload; the L1 export is mounted read-only; the PG data is a tmpfs; containers and the network are removed at the end, also on failure).

- **How:** `TRIAL_AMD64_DOCKER=1 TRIAL_CODE_HEAD=<40-hex> [TRIAL_CLASSES=<subset of the 4>] [TRIAL_IMAGE_DIGEST=sha256:..] [TRIAL_EQ_REPO=.. TRIAL_EQ_PINNED_EXTRA=..] [TRIAL_BUDGET_S=..] run_trial.sh <git repo holding the head | export> <out>` = `trial_slice.py amd64-run` (`amd64_docker.py`, `amd64_probe.py`). The head is exported with `git archive` (sidecar, migrations, the three `035_DISCOVERY_LAYER` files); the image is built from the head's `platform/python-sidecar/Dockerfile.pipeline` with **one derived change** (an (I) INTERPRETATION): the ephemeris RUN step that fetches from GCS is replaced by a COPY of the pinned corpus `/Users/Dev/kalayantra/ephe` under the Dockerfile's own three sha256 checks (R-2026-10-15-02: never a network fetch); or an image already present locally is used **by digest** (never silently rebuilt). The run resumes (exit 75) with the PG container kept. The sibling PG is reached by sharing its network namespace (`--network container:<pg>`, PG on 127.0.0.1:55433), so the disposable-database guard sees an ordinary loopback server and is not relaxed.
- **Arch read inside:** `amd64_probe.py` runs in the container just before the slice and writes `runtime_probe.json` (`uname -m`, Python, CPU identity, the installed-distribution lock digest, this run's nonce). `runtime_block` builds `runtime {kind: qualifying_run, arch: linux/amd64, python, dependency_lock_digest, emulated, arch_probe}` from it ONLY; there is no way to pass an architecture from outside.
- **Emulation recorded:** `detect_emulation` reads the engine architecture (`docker info`) and the container's CPU (Rosetta = vendor `VirtualApple`, QEMU = a QEMU model, else `undetermined`). The note goes to `provenance.platform_notes.emulation` of the EQUIVALENCE_RECORD (E6, never compared — E4 is identical to a native run's) and to the report's `platform` block.
- **G-5:** `platform.wall_comparable: false` makes every wall-time check of G-5 (projection, effective wall, verifier solver check) read NOT_EVALUATED, whatever the class count and load (`gates.wall_comparability`; SR-G5-LOAD). The slice wall is recorded in `amd64_run.json` for sizing only.
- **equivalence_record.py (EQ-16):** a container run (`runtime.emulated` / `arch_probe` present) is refused without an `arch_probe` {source in_container, uname_machine x86_64, sys_platform linux} agreeing with `arch`, and — when emulated — without `provenance.platform_notes.emulation` {emulated true, layer rosetta|qemu|undetermined}; `platform_notes` is a new closed provenance key.
- **4-class slice only** (a subset for a smoke); one slice per head (the out directory belongs to one head). Oracles `tests/test_amd64_docker.py` (AD-1..AD-10) and `fleet/tests/test_equivalence_record.py` (EQ-16); planted reversions `mutants_amd64.py` (23 harness + 3 EQ-16, 26 of 26 killed); `amd64-finish` finishes a run whose driver was killed after the container ran to its end (AD-10).
