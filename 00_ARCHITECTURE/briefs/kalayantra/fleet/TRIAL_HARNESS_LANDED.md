## HARNESS-3.2 (item H-1: PRETR-3a D-8, D-9, D-10)
Three fixes to what the harness measures, each with one oracle and one planted reversion (`tests/test_harness_32.py`, `mutants_h32.py`, run by `mutation_check.py H-`):

- **H-a / H-a2 (D-8)** the G-6 cross-check rebuilds a window with the writer's own operand sources: the vedha source is `vedha_source()` bound per grain with `for_grain(..., position_at=)` (the post-`od1-vedha-residence` signature — the cross-check needs a head that carries that lane and says so by name when it does not), a P1 grain is read with the P1 operand sources, and the whole rebuild runs under `rule_profile(final_rules=True)`.
- **H-b (D-9)** G-4's verdict is `generation_verdict(..., classes=<the trial classes>)`. The scoped form does not carry the aggregate-only checks (pinned-universe coverage, shard stamps, G-6 evidence, wall rule); the report says so (`verification.generation_verdict_scope`, G-4 `verdict_scope`), and they stay covered by the R8/R8X fixtures and the seal verification job.
- **H-c (D-10)** G-5's projection claim reads NOT_EVALUATED (never FAIL or PASS) when the slice has fewer classes than the trial profile requires (12), or when the busiest 1-minute load per core of any writer stage exceeded `runtime.max_load_per_core` (sampled per stage by the effective-wall clock, stored in `effective_wall.stages.*.max_load_per_core`), or when no load was recorded. The default bound 1.0 is an (I) INTERPRETATION; the profiles carry `max_load_per_core_ruling: PLACEHOLDER-SURROGATE-RULING-G5-MAX-LOAD-PER-CORE` — the final value is a surrogate ruling. A final profile that states no bound fails a check.
