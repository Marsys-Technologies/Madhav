**PART A — for the owner**

**Nearest.** How soon the window opens: whole days from the date the question is asked to the day the window starts. A window already open counts as zero; one that has already closed is not a candidate (listed as elapsed, never silently dropped). Sooner is better. Two windows tie when their start days are within one day of each other — the forecaster states its windows to the day and no finer.

**Strongest.** How much more the independent schools agree during the window than chance would give — the jury's own signed, measured incremental agreement, exactly as the jury stores it. Higher is better; a negative value still compares. Two windows tie when they differ by less than one day of one witness's boundary moving on the shorter judge window. The jury's pass/fail qualification is shown beside it, never used to order. **Not available yet:** the jury's rows are not joined to the served windows, so every window reads "strongest: information unavailable" and no window can beat another until that join is admitted (the jury generation goes live at the production cutover). The old convergence score is never substituted.

**Most robust.** Whether the window survives the forecaster's five checks: all five ayanāṃśas, birth-time uncertainty, two daśā systems concurring, exceeding its own null, citations resolving. The tier is the weakest of the five — the forecaster's own rule — with the weakest link named. Higher tier is better; same tier is an exact tie. No check-counting.

**Best suited.** Only when a question frame is given: does the window's event belong to the domain asked about, and how much of it lies inside the dates asked about — the forecaster's own relevance rule against its thirteen event domains. Higher is better; ties within one day's worth of overlap. A domain word outside the thirteen makes it unavailable, stated. A named entity is echoed, not judged: no window carries entities today.

**First release, the user sees:** the windows ahead, most-robust first then soonest, each with days-ahead, robustness tier and weakest link, "strongest: unavailable (jury not yet joined)", relevance if a frame was given, obstruction state where known — and every pair marked "incomparable: strongest unavailable" rather than a winner.

**Cut as over-governance:** retirement dates, registers, review-of-review steps, and any "rule later" clause — the table below is complete now.
Also cut: weights, the legacy score as fallback, any confidence reading of the jury's null, invented entity matching, obstruction- or count-based robustness.

**Ruling text to record (K7-4 Q7, owner-delegated 2026-10-13):**
> K7-4 comparison table. Candidates are `kala_field_windows` rows; elapsed windows are rejected `window_elapsed`, listed. `nearest` = whole days from `date_from` to `window_start` (0 if open), lower better, tolerance 1 day (day_grade). `strongest` = `kala_jury_candidate.conditional_effect` as stored (D(W), witness-groups), higher better, tolerance 1/min(anchor_days) of the pair, verdict carried not applied; NULL or unbound → `information_unavailable` with reason; the legacy convergence score is never substituted; live windows read unavailable until the stage-to-reader identity mapping is admitted. `most_robust` = `kala_field_windows.confidence_tier` ordinal (structural_prior < concurrent < calibrated_provisional < calibrated), higher better, tolerance 0, weakest_link carried, no dimension counting; NULL → unavailable. `best_suited` exists only with a `question_frame`: `compute_relevance(ontology.domain(event_class), window_start, window_end, ∅, frame{domain, horizon = date_from..date_to})`, higher better, tolerance 0.3/H_days; frame domain outside the ontology's thirteen → unavailable; entity echoed, not evaluated. Dominance requires every axis available on both sides; any unavailable axis → `incomparable: unavailable`; opposed strict wins → `incomparable: tradeoff`. Presentation: most_robust → strongest → nearest; best_suited leads when a frame is given; declared as `order_policy`, never alters evidence. Tolerances carried in the result. Negative-space `effective_state` and jury `contest_rows` are carried annotations, not axes. No weights.

**Interpretations, each the conservative reading:** (I1) nearest from `window_start`, not `peak_date` — the start is the earliest moment the window matters and is the only field with declared day-grade semantics; peak is shown beside. (I2) the strongest tie band is the stored anchor-interval bound on one-day boundary sensitivity — exposure itself is not stored; if the producer later stores it, it replaces `anchor_days` without changing the rule. (I3) tier order is the producer's own encoding, not a new scale. (I4) relevance computed at serve time with the producer's own function because the stored factor is frame-less. (I5) best_suited leads only when the user supplied a frame — it is their stated question; order never touches evidence. (I6) unavailable on either side voids the whole pair, the strict reading of the owner's ruling; the result names the cause so a tradeoff is never confused with a data gap. (I7) obstruction and contests are typed facts whose producers emit no ordering, so they annotate and never rank.
