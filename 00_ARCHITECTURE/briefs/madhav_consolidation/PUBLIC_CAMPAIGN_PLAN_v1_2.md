# Madhav consolidation campaign

Preserve the Madhav experience and the background work that supports it. The campaign covers chart workflows, APIs and MCP, computation and serving, authorization and stored data, operations and recovery, research provenance, instructions and CI/CD. [CCD-030](../../CROSS_CUTTING_DECISION_REGISTER_v1_0.md#ccd-030--madhav-consolidation-v12-source-publication-and-protected-execution) records owner direction and source authority.

| Responsibility | Boundary |
|---|---|
| Product and runtime | Own user journeys and public contracts. Preserve role, chart scope, saved links, partial readiness, frame, empty and degraded behavior. |
| Architecture, data and research | Map the six domain layers, registered writers, non-writer services and serving interfaces as typed relationships. Preserve L1 fact authority, derivation provenance, writer transaction rules and held-out isolation. Build/Operations owns explicitly qualified maintenance transitions. |
| Instructions | Preserve authoritative root and scoped instructions, stable anchors, local UI decisions, effective client scope and fail-closed validation. Keep historical records traceable. |
| CI/CD and recovery | Keep current required checks and protected ordering. Trace actual build inputs and event selection. Verify source, artifact, migration compatibility, runtime identity and recovery before delivery acceptance. |
| Integration and verification | The integration lead assigns disjoint scopes and coordinates shared changes. Independent verification reproduces exact-candidate results. Strategy resolves contested decisions within delegated authority. |

Run discovery lanes concurrently. Each slice can advance once its own dependencies, write scope, behavior baseline and rollback proof are ready. Compare candidate behavior to representative supported, degraded, rare and historical flows. Keep source, installed cutover and retirement evidence separate. Use the [worktree protocol](../../WORKTREE_ISOLATION_PROTOCOL_v1_0.md) and [hygiene rules](../../ONGOING_HYGIENE_POLICIES_v1_0.md).

The first scopes are deploy-input selection and diff failure handling, supported client qualification for governance validation, and extraction of the guarded Chart Folio identity read. A later architecture slice must preserve the chartless Panchanga path and scope any chart overlay to an authorized viewer and authoritative L1 provenance. Each repair preserves existing protections and has independent tests and a reversible candidate.

Closure requires evidence of safe retirement, conforming component and data boundaries, correct effective instructions, intact CI/CD and preserved product, research and recovery behavior. Lack of an import or recent execution is insufficient to retire a route, writer, schedule, migration or recovery path. Preserve applied history and research reproducibility. Keep unresolved dependencies visible and retain their paths while scope or evidence remains open.
