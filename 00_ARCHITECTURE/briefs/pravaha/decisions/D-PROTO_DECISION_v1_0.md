## 2. Decision

Protocol v2.2 is a sound, pre-registered, falsifiable contract and is **accepted, subject to five mechanical conditions** that Stream B lands as a versioned v2.3 amendment and the steward verifies before B4.6 marks the protocol ACCEPTED. The case for acceptance is concrete: every pass/fail threshold (45 d, 25th percentile, 182-d cap, 3·n_c·90/H, the 0.5–40 % gain band, the 95 %/0.5 % horns, the 50 % era and plateau tests) was fixed in v1.0–v2.0 before any candidate existed and none moved in v2.2; the registry reconciles exactly to the LEL (all 57 source IDs exactly once, every anchor line correct, every grain faithful); every headline figure of the '3.0' re-run reproduces to the digit, including byte-identical controls; the honest states (`INPUT_REJECTED`, `VOID`, `RANK-UNPROVEN`, `UNVERIFIABLE`) are real code paths, not labels; and Codex's five D-PROTO amendments and R3-P01 are delivered in substance. The conditions exist because two things I found would let a future '5.0' score mislead: the gain-class 0.5–40 % base-rate band, stated as a T-FP criterion in every protocol version since v1.0 (P:183–184), is printed but enforced nowhere in code, so an over-broad gain-side candidate can pass every enforced endpoint; and the scorer's candidate-set rule disagrees with §6.1 for the two new two-year interval rows and ignores the observation mask for the two 2026 rows, both of which the reconciliation claims as frozen. Each condition is a few lines of prose and code, none is a redesign, and each is checkable by a re-run whose '3.0' figures must not move. No further independent review round is required for these; anything beyond the listed conditions returns to the native. Codex's third REWORK was earned by the artifacts it reviewed; what remains now is decision-relevant but small, and holding the campaign for another full round would be disproportionate.

## 5. Findings

**F1 — decision-relevant · The gain-class base-rate band is printed, not enforced; an over-broad gain-side candidate passes every enforced endpoint.**
Evidence: P:183–184 states under T-FP "Gain classes keep the two-horns rule: 0.5 % ≤ base rate ≤ 40 %", as v1.0 (EVALUATION_PROTOCOL_v1_0.md:112–113) and v1.1 (…v1_1.md:44–47) did as a pass/fail criterion. SC:229–236 computes `t_fp` for the 9 adverse classes only; SC:237–245 prints gain-class bands as a tally with no `pass` field; RR:235–281 carries no gain entry; the generation verdict nowhere consumes the band. The T-rank exclusion threshold is 95 % (SC:146), so a gain class at 60–90 % is neither T-FP-failed nor rank-excluded.
Consequence: a candidate admitting ~90 % of days in every gain class would hit ~34 of the 38 non-adverse held-out events (T-cover passes at 32/47), keep its adverse classes inside 2.6 % (T-FP passes), avoid the era fingerprint by non-identical boundaries, and stay rank-eligible. With the band enforced, blanket gain coverage is capped at 40 % and the expected blanket T-cover falls to roughly 15/47, so the 32/47 bar again implies real signal. This is exactly the "way for an over-broad candidate to pass" the packet asked me to hunt for.

**F2 — decision-relevant · For interval events the scorer's hit test disagrees with §6.1; the controls use the prose semantics.**
Evidence: P:156–161 defines a T-cover hit as any admitted window of the class overlapping the event's scored span (interval: the interval). SC:125–130 takes candidates from `in_year(cls, start_year)` and tests overlap only within that subset. Synthetic probe (in memory): a lone chronic_onset window 2008-03-01→2008-05-30 against [2007-01-01, 2008-12-31] is a **miss** under SC and a **hit** under P. The control draw (SC:262) tests overlap against all merged windows, so controls and endpoint use different overlap semantics for these rows. '3.0' is unaffected (its era windows touch 2007 and 2021), which is why no figure moved.
Consequence: on two of 47 held-out events a '5.0' can be scored a false miss; at the 32/47 bar that is enough to flip a verdict.

**F3 — decision-relevant · Observation-mask treatment of the candidate year is claimed frozen, absent from the protocol, and unmasked in code.**
Evidence: RC:48 records R2-M04 as closed with "observed-year masking frozen"; P has no rule for it (only P:102–103 on coverage intersection); SC:108–110 takes the full calendar year, so for the two 2026 rows (EVT.2026.01.XX.01, EVT.2026.03.20.01) windows dated after 2026-04-17 enter N and the ranking. Probes: one in-mask window plus two post-mask windows gives N = 3 (eligible) where in-mask N = 1; a rank-2-of-2 hit (percentile 50) becomes 2-of-5 (percentile 20, passes ≤ 25) after three lower-si post-mask windows are added.
Consequence: a candidate's percentile on 2 of 32 events can be flattered by rows outside the observed horizon, and its eligibility count inflated toward the floor of 17.

**F4 — decision-relevant · T-honesty's consequences for a candidate are undefined.**
Evidence: P:185–190 defines `unqualified` (coverage < 50 %) and `UNVERIFIABLE` (no manifest); P:192 fails a generation on "failure" of a co-primary endpoint. Neither state is defined as failure; SC:275–277 hard-codes `UNVERIFIABLE` with no `pass` field and no consequence; and P does not say what happens to the held-out events of an `unqualified` class ("not scored" is ambiguous between "excluded from the denominator" and "counted as misses"). Formula for the coverage fraction is not stated.
Consequence: read leniently, a candidate that never computes its hardest classes (e.g. education_milestone, where '3.0' misses 9 of 10) could shed those events, or ship without a manifest and sit at UNVERIFIABLE rather than FAIL. One paragraph closes both readings.

**F5 — decision-relevant (§N.8 class) · The result file asserts the extract hash rather than measuring it, and the class universe is not validated on input.**
Evidence: SC:31–33 writes `extract_sha256` as a string literal; SC:35–37 loads the file and asserts only `len(rows) == 914`; no `hashlib` call touches X (contrast SC:271, which does hash the controls). SC:144 derives the class list from emitted rows; an extract carrying a class outside the 27 (P:63–91) is silently admitted and, if non-adverse, treated as gain.
Consequence: a modified 914-row extract would produce a result file claiming the pinned hash — precisely the "status without a detector" the project's own §N.8 forbids — and the machine-readable class contract Codex asked for is unenforced at the input boundary.

**F6 — polish · "730 d" is stated three times for a 731-day interval** (P:204; ER:161–162; B:26–28, 103, 107) while P:104–106 correctly says "730 or 731 as the calendar gives", SC draws 731, and CT:847–849 records 731. Harmless to every figure; it sits in the paragraph that claims "prose matches the code exactly".

Probe: 0.54999999949 vs 0.54999999951 tie under one and differ under the other. Unreachable with two-decimal si; still a literal prose/code disagreement.
