# Rebuild and upstream sequencing

## 0. The answer in plain words (to be confirmed by the owner)
1. **Nothing upstream will be "elevated" soon — so do not wait for that.** The usable milestone is **"SETTLED"**, which Suvarṇa will announce twice: **SETTLED-1** (after her S-L1 rebuild; earliest 2026-10-04/05; everything except node values) and **SETTLED-2** (after node-series step 2/3; node values; **no date**). [FACT: decisions/SUVARNA_UPSTREAM_SETTLEMENT_ANSWER_20261003.md — "None of the 127 assets is ELEVATED (certified) today and S-L1 does not make them so… Wait for 'settled', not 'elevated'."]
2. **Yes, the Gochara data will be rebuilt** after the upstream settles — every upstream rebuild gets a new build id and generation even when values are identical, and the sealed generation is immutable, so a change upstream means a NEW generation, never an edit. [FACT: Suvarna answer (c); packet reviews/REVIEW_REQUEST_A5_5_GATE_v1_16.md §R10-2 (seal immutability, stale attestations refused)]
3. **The effort is protected by ordering the SEAL, not by waiting to BUILD:** a build (and its independent verification) may run earlier as an unsealed dry run; a seal is the irreversible act, so it waits for the right SETTLED notice. [ASSUMPTION — the steward's proposal under test; the facts below support it, with the caveats in §6.]
4. **The first (all-NULL) `'5.0'` candidate is NOT independent of the node series** — so its seal gate is **SETTLED-2**, unless Stream A confirms it can be made independent (§2). [FACT for the code reads below; the conclusion is B's reading — ASK via the steward.]
