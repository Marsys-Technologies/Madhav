The fix is one predicate, and the cheaper direction is to drop `asset_throughput` from it everywhere — a `'dormant'` cache-bust row is not runtime evidence; receipts and build-run rows are the build-attested evidence, and the authors' own argument is that they already imply throughput.

### 5.5 Self-cancelling — the expiry has no exit (F-R20-3)

Every successful data-writer run persists a receipt in its success transaction (`asset_runner.py:1394 capture_and_persist_receipt` → `provenance.py:244–276 persist_successful_receipt`, upsert keyed `(asset_id, scope_key, partition_key)`). "Self-cancelling" is the correct direction for a stray receipt; it is the wrong behaviour for the one run the dispatch script exists to perform.
