# What 1240 must respect (numbered; each is a source fact, not a preference)

1. **Position and window.** Number **1240** (reserved block 1230–1249; run `guard:migration-numbers`). It creates a table and a **trigger on `ka_gochara_generation_seal`** (a 1153 table), so it belongs in the **protected window**, after 1233: **1204 → 1206 → 1232 → 1233 → 1240**. Wire it exactly as 1232/1233 were: `migrate.ts` `PROTECTED_PUBLIC_SCHEMA_MIGRATIONS` + its message, `deploy.yml` (`migrations+=(…)` after 1233 and the input description), `tests/unit/jataka_schema_capability.test.ts`, `tests/unit/migrations/gochara_a5_1_contract_static.test.ts` (`V15_AMENDMENTS`). **Never edit** 1153–1157, 1206, 1232 or 1233. Gate it like 1233: required relations/functions present, not already applied, no `BEGIN/COMMIT` (migrate.ts owns one transaction per file), presence checks at the end.
2. **Seal interaction — ONE additive BEFORE-INSERT trigger, fired after 1206's.** `ka_gochara_seal_generation` (1153) is `INSERT … ON CONFLICT (chart_id, generation) DO NOTHING`; the BEFORE-INSERT triggers fire first, in **name order**: `ka_gochara_generation_seal_write_guard` (1153) → `ka_gochara_generation_seal_z_search_complete` (1206). Add exactly one more, named to sort **after** `_z_search_complete` (e.g. `ka_gochara_generation_seal_zz_window_verified`). **Do not replace** the 1153 or 1206 guard functions. Take the locks in the order those guards already hold (chart EXCLUSIVE, then global SHARED — re-entry is idempotent); **no new family key**, no global EXCLUSIVE (lock-order ruling B).
3. **The REPLAY branch is mandatory.** A replay of an existing seal hits the BEFORE trigger first (1206 distinguishes `FOUND` existing seal ⇒ replay). The new guard needs the same two branches: **(a) first seal** — the gate; **(b) replay** — a generation **sealed before 1240 has no verification rows and must still replay cleanly** (never retro-require them); if rows exist, re-check only that they still agree with the stored, frozen windows. **Replay never reads today's catalogue** (the AM-16 historical-replay principle).
4. **Who may write — the verifier role only.** `data_plane_builder` gets **no** INSERT/UPDATE/DELETE on the new table (the writer cannot verify itself; today 1206 §7 *does* let the builder write the inventory verification table — do not repeat that). The verifier principal (`gochara_verifier`, not yet provisioned in production) gets **INSERT** and, **pre-seal only**, **DELETE** (re-verification replaces) — enforced by the write guard, not by trust. The sealer gets **SELECT** on the table and EXECUTE on the gate's functions (the trigger fires as the sealing role). Grants are **explicit**, **guarded by `IF EXISTS (… pg_roles …)`** like 1206 §7 (the verifier role does not exist in production yet), and **table-level** privileges only.
5. **Least-privilege functions, derived the 1206-R6 way.** Production's default privileges revoke PUBLIC EXECUTE on everything `amjis_app` creates. Every function the gate and the write guard call **as the invoking role** needs an explicit `GRANT EXECUTE` (to the verifier/sealer as appropriate). Derive the list by running the real flow under the deployment-faithful role mirror and adding one grant per `permission denied for function X` until it converges; the live suite is the detector. **No `SECURITY DEFINER`** anywhere; functions `SET search_path = pg_catalog, public`.
6. **Write-guard pattern — copy 1206's, not 1155's.** 1155's `ka_gochara_chart_write_guard` keys its modes on the table name; do not edit it. Create the new table with the 1206 trio: `_0_statement_lock` (BEFORE UPDATE/DELETE FOR EACH STATEMENT → `ka_gochara_chart_statement_lock`, the chart key **before** any tuple lock), `_1_write_guard` (chart key first; **a sealed generation refuses INSERT/UPDATE/DELETE**; READ COMMITTED only — the lock helpers refuse other isolation), `_no_truncate` (`ka_gochara_refuse_truncate`). The row's header precondition mirrors 1206: a verification row requires an existing **finalised** inventory for (chart, generation, class) and the windows it verifies.
7. **Key and CHECKs.** PK `(chart_id, generation, event_class, path_id, rule_version)` — composite version-bound; FK `(path_id, rule_version)` → `ka_gochara_rule_path`; FK chart → `charts` (one chart, D-SCOPE); `generation` CHECK `ka_gochara_generation_governed`; `event_class` CHECK = 1206's list; `status IN ('VERIFIED','UNVERIFIED_DYNAMIC','FAILED')`; counts ≥ 0; hashes `^[0-9a-f]{64}$`; objective name a token; structured qualification provenance as JSONB with a **named, closed-key shape CHECK** (like `coverage_facts`).
8. **The gate (first seal) — what it must refuse, set-based and cheap.** For every `(class, included path pin)` that has stored windows: refuse **no verification row** (an omitted expected window/path), **status ≠ VERIFIED** (`UNVERIFIED_DYNAMIC` and `FAILED` may be stored as diagnostics but never pass), `expected_window_count` ≠ the stored count, `expected_window_set_digest` ≠ the SQL-recomputed digest of the stored windows (a **stale** row after any window change), or **field coverage** short of the full governed-field list. The expected set is derived from the **stored windows and the 1206 pins** — never from a count the writer supplies.
9. **Digest functions — encode floats exactly.** `evidence_for/_against/score/severity` are `REAL`; `to_jsonb(real)` text is not a safe preimage. Hash the **IEEE bits** (`float4send`, hex) or a fixed-format text, with **NULL distinct from JSON null**; reuse `ka_gochara_canonical_json`/`ka_gochara_sha256_hex`; ship a **frozen literal preimage + expected hash** vector in a static test (as `am16_vectors_frozen_v2.json` does) so serializer drift fails CI.
10. **Persisting what the window row drops today.** `WindowStore.replace_grain_windows` discards `objective`, `objective_value` and the detailed unqualified reasons (R8-4). If they live **on the window**, that is a second additive change on the 1156 table (nullable columns, named CHECKs) — the 1233 pattern: a **sealed generation stays frozen automatically** because the chart write guard compares `to_jsonb(NEW)` with `to_jsonb(OLD)`; if they live **on the verification row**, the verifier must be able to reconstruct them from bound inputs. Either way the gate checks them (Codex R8-4: "lossless, mandatory reconstruction").
11. **Tests Stream A owes (live, deployment-faithful mirror: objects owned by `amjis_app`, PUBLIC EXECUTE revoked, builder + sealer + verifier roles; PG15):** builder INSERT refused; verifier INSERT accepted; seal refused for each of {missing row, `UNVERIFIED_DYNAMIC`, `FAILED`, count mismatch, stale digest after a window edit, short field coverage}; seal accepted when all `VERIFIED`; **replay of a pre-1240 sealed generation passes**; sealed generation frozen (UPDATE/DELETE/INSERT refused); a static contract test (no `BEGIN/COMMIT`, exactly one new trigger on the seal table, no edit of applied files, grants table-level, no `SECURITY DEFINER`); a mutation check that neuters each guard in turn; and the rehearsal script's S4 matrix extended with the new principals.
12. **Do not:** weaken any 1206 check; add a fourth lock family; read the writer's own output as the expected set; grant the builder anything on the new table; rely on the deploy-time runner without VERIFYING the migration applied (CLAUDE.md §N.4).
