# Design review: L1 graha-level argala rows (AR-1 to AR-6 as ruled)

## 0. What is ruled, and what goes to J1 by name

AR-1: L1 owns the pairing **2-12, 4-10, 11-3, 5-9**; obstruction applies to benefic and malefic argala; the canonical outcome is by count (argala count > obstructor count = `argala_prevails`; fewer = `obstructed`; equal = `undetermined`), and the any-obstructor reading is stored beside it as a named variant (change 1 below). AR-2: for **both nodes**, when the node is the reference, argala and obstruction are counted in reverse, in the L1 graha-level rows (`count_direction`); Ketu-only is the named stricter variant; the sign matrix stays forward-only. AR-3: an empty source sign is NULL with `no_occupant`; the 1.0 / 0.25 formula stays as a labelled project convention (`unsourced`). AR-4: tier stays `single`, provenance string corrected. AR-5: chapter 31 chunk ids, `sourced_ocr_unverified`. AR-6: {2,4,5,11} / {12,10,9,3} canonical, {2,4,11} a named filter; L1 adds a graha-level family, D1 only; L2 builds from those rows; vipareeta and the 3rd-house evil argala are recorded, not built.

**Goes on the J1 reviewers' list by name:** (1) the pairing 2-12, 4-10, 11-3, 5-9 (the 11-3 pair rests on the worked example, because the translator's note is OCR-garbled; the 5-9 pair rests on one sentence); (2) the reversal for both Rahu and Ketu; (3) **argala outcome rule: count vs any-obstructor** (which reading is canonical).

**The outcome is two named readings, not one field (SS change 1).** The BPHS worked example (`bphs_pg0312_c01`) calls all three argalas "countered". The explicit rule in both texts is "the argala prevails if its planets outnumber the obstructors, or if they are stronger" (`bphs_pg0311_c01`; Jaimini Su. 8). Applied to the example, the count rule gives Mars (1) vs Saturn (1) = `undetermined`, Sun-Mercury (2) vs Venus (1) = `argala_prevails`, Jupiter (1) vs Moon-Rahu (2) = `obstructed`; "countered" for all three is the any-obstructor reading. So the rows store the facts and both readings: `obstruction_present`, `argala_count`, `obstructor_count`, **`outcome_by_count`** (CANONICAL, carried by `fact_value_text`: the explicit rule outranks an illustrative word) and **`outcome_any_obstructor`** (`obstructed` whenever `obstruction_present`, else `unobstructed`; the named variant, matching the worked example's wording and today's L1 virodha score). `formula_provenance_text` says which is canonical and why. "Stronger" stays null (no sourced measure). The two readings differ a lot on the canonical chart (section 3: 2 against 13 obstructed of 32), which is why the choice is on the J1 list. The golden test asserts both readings on the worked example.

Node reversal: for T in {Rahu, Ketu} the source sign of offset k is `((sign_T - 1) - (k - 1)) mod 12 + 1`, for the argala offset and for its paired obstruction offset. **Sign-matrix changes that ride along (AR-3, AR-4, AR-5).** An argala-offset cell with no occupant in the source sign stores `fact_value_num = NULL`, `fact_value_text = 'no_occupant'` (still 144 rows per varga, so the writer's count assertion and conjunct (h27) hold); occupied cells keep the formula. **Idempotency.** `_insert_chart_facts_rows` calls `replace_prior_chart_facts` over the (chart, ayanamsha, category) scope present in the batch, so the new category is deleted and re-inserted per chart x natural key with no new code; `fact_id` is `sha256(category|subject|key|chart|ayanamsha)`, stable across builds. ## 2. (b) L2: naming, consumers, and the one malefic definition

**Naming accepted by SS: `argala_by_malefic` / `argala_by_benefic`.** **`virodha` means obstruction everywhere.** L2's `argala_virodha` means "argala by a malefic" (`bo_karanajala.py:543`) while L1 and `get_argala.ts` use virodha for the obstruction. Proposal: **`argala_by_malefic`**, with `argala_by_benefic` replacing `argala_positive` for symmetry (both name the causer and claim no valence; BPHS itself says a malefic's argala can be favourable, `bphs_pg0314_c02`). `argala_virodha` is then reserved for an obstructor edge, which is not built. I did not pick the classical pair subhargala / papargala: `subhargala` is in the corpus (`bphs_pg0311_c02`, `bphs_pg0314_c02`), `papargala` is not. Minimal-blast alternative: rename only `argala_virodha` and keep `argala_positive`.
