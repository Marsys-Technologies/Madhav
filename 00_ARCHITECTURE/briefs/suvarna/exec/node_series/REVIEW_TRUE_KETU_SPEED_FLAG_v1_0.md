## 0. Answer in five lines
1. **Correct them** (`speed_dps` and `is_retrograde` := Rahu's for the same date and `ayanamsha_id`, TRUE rows only, 91,676 rows, two columns), but **fix the writer first**: today's `bg_ephemeris` recomputes the inverted values and its upsert rewrites rows that differ, so ANY rebuild (including step 2) would revert a prior data correction.

## 6. The D6 UPDATE plan (design only; never run): plan text and hash
`ketu_update_plan_text_v1_0.txt` in this directory is the plan text; its sha256 is **`e0a7bd65455cd3ca9205db80f4dd3f3a119387877037f3bf2053902e63936669`** (a hash of the plan TEXT; the executor does not exist yet and would embed its own sha256 in a final plan, like `d6_index/`). The statement:
```sql
UPDATE public.ephemeris_daily k SET speed_dps = r.speed_dps, is_retrograde = r.is_retrograde
FROM public.ephemeris_daily r
WHERE k.body = 'Ketu' AND k.node_mode = 'true' AND r.body = 'Rahu' AND r.node_mode = 'true'
  AND r.date = k.date AND r.ayanamsha_id = k.ayanamsha_id
  AND (k.speed_dps IS DISTINCT FROM r.speed_dps OR k.is_retrograde IS DISTINCT FROM r.is_retrograde);   -- rowcount exactly 91,676
```
Mechanism, gate and evidence are those of `d6_index/` (PR #2932): transient membership of `amjis_app` by the Cloud SQL admin in one transaction, `run_gated.sh` (non-completed `main` deploy runs = 0 and planned/running/paused `build_runs` = 0, read in the same invocation), snapshots before/after (ACL, owner, RLS, policies, memberships, indexes, constraints), the before-image of all 91,676 rows and a reversal UPDATE written BEFORE the statement, dry run always rolls back, `--apply` needs `--expect-plan` and `--expect-evidence`. Pre-checks refuse unless all 91,676 pairs show Ketu speed = −Rahu speed (non-zero), opposite flags and longitude = Rahu + 180 within 1e-6. Post-checks: rowcount 91,676; E3 counts 0; `non_node_digest_v1` and the TRUE Rahu digest identical; every other column of every Ketu row byte-identical; ACL/owner/membership/index/constraint snapshots equal. **Precondition (not readable from the database): the corrected writer is merged and deployed**, else a rebuild reverts it. Note: an UPDATE by the table owner needs no CREATE on schema `public` (unlike the index), so the same change could also be a guarded migration run by the routine runner; SS's choice of route; the D6 form is proposed because it carries evidence, a reversal and the gate. `computed_at` and `source_citation` are left as they are (the correction is recorded in the evidence directory and F-L0-08, not in the row).
