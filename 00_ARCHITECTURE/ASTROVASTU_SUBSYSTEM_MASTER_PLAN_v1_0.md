# Astrovastu Subsystem — Master Plan (maximal-for-its-scope) v1.0

## §0 — Honest reframe (the placement matters more than the depth)

Astrovastu (the Astro-Vastu lineage) fuses Vastu directional science with the natal chart: each direction →
planet → element → life-domain, and the method reads which directions are activated/afflicted (from the
chart's weak planets) and prescribes DIRECTIONAL remedies. **Its deterministic content is thin** (a direction-
mapping reference + a weak-planet join that mostly reuses Dignity); **its real value is remedial + dependent
on the person's physical space (which the chart doesn't contain).** So: build the deterministic part fully
(it's small) at L0+L1, and place the real content as a TIERED remedial tradition in the existing remedial
layer — NOT as a standalone deep subsystem. Maximal *for what it deterministically is*.

## §1 — Three-data-category split
- **STATIC → L0 (`bg_vastu_directions`):** the complete directional reference (chart-agnostic, cited).
- **CHART-SPECIFIC → L1 (thin — a derived join):** weak-planets → their directions (reuses ga_condition).
- **REMEDIAL → bo_upaya (L4):** the Astrovastu directional remedies as a tiered tradition.

## §2 — L0 `bg_vastu_directions` (maximal directional reference, cited)
- **The 16 directions** (8 main + 8 sub) → planet ruler → element (pancha-tatva) → life-domain → presiding
  deity → favorable/unfavorable activities per direction.
- **The Vastu-Purusha Mandala** — the full 9×9 (81-pada) grid with all **45 devata positions** (the deities
  occupying the mandala) + the Brahma-sthana (center) + the marma (sensitive grid points / energy-lines).
- **Direction → remedy associations** (which corrective for which afflicted direction — the remedy CATALOG,
  cited; the application is serve-time/bo_upaya).
- **The planet → direction → body/domain correspondences** (Dik-Bala already touches this — cross-reference;
  Disha-Shul from panchanga touches it too).
All cited to the Vastu/Astrovastu corpus → into bg_texts.
**Note:** this reference is useful BEYOND Astrovastu — Dik Bala (directional strength, A8) and Disha Shul
(A4) use the same direction data; bg_vastu_directions becomes the shared directional authority.

## §3 — L1 (thin per-chart join — almost no new computation)
Per chart: the weak planets (REUSE ga_condition — don't recompute weakness) → their associated directions
(via bg_vastu_directions) → "these directions of your space warrant attention." A JOIN. Plus the chart's
Dik-Bala directional-strength picture (reuses A8). Small; deterministic; cited.

## §4 — bo_upaya (L4) — where the real content lives (TIERED remedial tradition)
Astrovastu directional remedies become a TRADITION within the existing 6-tradition × 18-category remedy
matrix in bo_upaya. **EPISTEMIC TIER: a remedial RECOMMENDATION cited to the Astrovastu source, clearly
flagged as the tradition's suggestion — NOT a deterministic fact** (the contamination guardrail; Vastu
remedies don't fit the falsifiable-prediction frame, so they're tiered out of the deterministic base). The
remedy is space-dependent (needs the person's actual home) → surfaced as guidance, not computed certainty.

## §5 — L2 (light)
The weak-planet→direction join surfaces as a remedial-context signal feeding bo_upaya; not a deep L2 graph
participant (Astrovastu isn't a structural-relationship system).

## §6 — Standards + the tiering
Computed-and-cited for the L0 reference + L1 join; the remedies tiered (remedial-tradition, NOT hard-fact —
explicitly marked, never mixed into the deterministic base). L0 ON-CONFLICT / L1 delete-then-insert;
orchestrator-native; cited; floors-aspirational; surgical migrations. bg_vastu_directions = the shared
directional authority.

## §7 — Decisions upfront
1. 16 vs 32-direction granularity (recommend 16 main+sub). 2. Mandala depth (45-devata + marma confirmed).
3. Remedy tiering wording in bo_upaya (the "tradition suggests" marker). 4. Whether bg_vastu_directions also
formally backs Dik-Bala/Disha-Shul (recommend yes — one directional authority). 5. Source editions (the
Astrovastu/Vastu corpus into bg_texts).
