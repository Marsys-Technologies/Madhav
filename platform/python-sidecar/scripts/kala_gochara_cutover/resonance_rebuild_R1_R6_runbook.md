## 4. Rollback (refuse-unless-verified; exact preimage certified)

Rollback restores **from the §1 snapshot table** (the native's own write).
The rebuild is per-chart scoped (DELETE WHERE chart_id … + INSERT inside one
orchestrator transaction), so a failed build rolls back atomically and the
prior partition is untouched; the coverage gate additionally refuses to
replace the partition on incomplete event-class coverage. If a completed
rebuild must be reversed, run the block below with THIS run's snapshot table
name and the count / FULL-ROW digest recorded in §1. The block REFUSES —
before any DELETE — when the snapshot table is absent, EMPTY, carries another
chart's rows, or does not match the recorded count/full-row certificate
(stale or incomplete); it then restores the exact preimage (all columns, ids
and computed_at included) and re-verifies the restored partition against the
same certificate. Any RAISE leaves the partition untouched (the transaction
aborts). The generator refuses to render a block for a zero recorded count.

```sql
BEGIN;
DO $rollback$
DECLARE
  snap_count BIGINT;
  snap_digest TEXT;
  foreign_rows BIGINT;
BEGIN
  IF to_regclass('gochara_resonance_map_snap_482012f1_20260930000000') IS NULL THEN
    RAISE EXCEPTION 'ROLLBACK REFUSED: snapshot table gochara_resonance_map_snap_482012f1_20260930000000 is absent';
  END IF;
  SELECT COUNT(*) INTO foreign_rows FROM gochara_resonance_map_snap_482012f1_20260930000000 WHERE chart_id <> '482012f1-710e-4a25-994a-93821f5871aa';
  IF foreign_rows <> 0 THEN
    RAISE EXCEPTION 'ROLLBACK REFUSED: snapshot gochara_resonance_map_snap_482012f1_20260930000000 carries % rows of another chart', foreign_rows;
  END IF;
  SELECT COUNT(*),
         COALESCE(md5(string_agg(row_to_json(t)::text, E'\n' ORDER BY t.id)), 'empty')
    INTO snap_count, snap_digest
    FROM gochara_resonance_map_snap_482012f1_20260930000000 t WHERE t.chart_id = '482012f1-710e-4a25-994a-93821f5871aa';
  IF snap_count = 0 THEN
    RAISE EXCEPTION 'ROLLBACK REFUSED: snapshot gochara_resonance_map_snap_482012f1_20260930000000 is EMPTY — never a rollback anchor';
  END IF;
  IF snap_count <> 177 OR snap_digest <> '00000000000000000000000000000000' THEN
    RAISE EXCEPTION 'ROLLBACK REFUSED: snapshot gochara_resonance_map_snap_482012f1_20260930000000 is stale or incomplete (count % full-row digest % vs recorded 177 00000000000000000000000000000000)', snap_count, snap_digest;
  END IF;
  DELETE FROM gochara_resonance_map WHERE chart_id = '482012f1-710e-4a25-994a-93821f5871aa';
  INSERT INTO gochara_resonance_map SELECT * FROM gochara_resonance_map_snap_482012f1_20260930000000 WHERE chart_id = '482012f1-710e-4a25-994a-93821f5871aa';
  SELECT COUNT(*),
         COALESCE(md5(string_agg(row_to_json(t)::text, E'\n' ORDER BY t.id)), 'empty')
    INTO snap_count, snap_digest
    FROM gochara_resonance_map t WHERE t.chart_id = '482012f1-710e-4a25-994a-93821f5871aa';
  IF snap_count <> 177 OR snap_digest <> '00000000000000000000000000000000' THEN
    RAISE EXCEPTION 'ROLLBACK FAILED VERIFICATION: restored count % full-row digest % vs recorded 177 00000000000000000000000000000000', snap_count, snap_digest;
  END IF;
END
$rollback$;
COMMIT;
```

Then confirm, read-only: the live partition's full-row certificate equals the
§1 recorded pair (the first §1 statement), and that another chart's
partition is unchanged (take its full-row certificate before and after with

Restoring the snapshot restores the PRE-WP3c (dishonest) rows — rollback is a
pause for diagnosis, never the end state. The fix direction is always data
forward, never a weakened guard. Drop the snapshot table only after the
rebuilt map has soaked.
